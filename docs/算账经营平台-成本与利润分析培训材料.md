# 算账经营平台 · 成本分析与利润分析 培训材料

本文档面向公司员工及领导，用于说明算账经营平台中**成本分析**与**利润分析**两个模块的作用、分析内容、背后逻辑，以及**材料成本构成**与 **LIFO（后进先出）** 的设计与原因。

---

## 一、平台定位与两个模块的关系

### 1.1 平台是做什么的

算账经营平台用于**废钢业务的成本与利润管理**，主要支撑：

- **看清花了多少钱**：采购/入库成本按业务类型、料型、时间维度汇总与对比。
- **看清赚了多少钱**：每笔销售的销售收入、材料成本、加工成本、利润，以及今日/本周/本月汇总。
- **支撑经营决策**：通过图表和明细，发现成本结构、利润结构及异常，便于调价、排产与考核。

### 1.2 两个模块的分工

| 模块       | 入口路径                         | 核心关注点                     | 主要数据来源                 |
|------------|----------------------------------|--------------------------------|------------------------------|
| **成本分析** | `/profit-management/cost-analysis`  | 采购/入库成本（花出去的钱）   | PurchaseWarehouse（采购入库表） |
| **利润分析** | `/profit-management/profit-analysis` | 销售与利润（收进来的钱、成本、利润） | DeliverySettlement + MaterialCostCache + ProcessingCostConfig |

- **成本分析**：不看销售，只看**原材料采购入库**——按单号、料型、日期汇总，区分「基地收货」「基地买货」「协同业务」。
- **利润分析**：以**钢厂结算（销售）**为维度，每笔销售 = 销售收入 − 材料成本 − 加工成本 = 利润；材料成本来自 **LIFO 计算并写入 MaterialCostCache**。

二者结合：成本分析看「进料花了多少」，利润分析看「出货赚了多少、材料与加工各占多少」。

## 二、成本分析模块

### 2.1 模块作用

成本分析用于回答：

- 今日/本周/本月**采购成本**多少？
- 成本在**基地收货（SH）、基地买货（TH）、协同业务**之间如何分布？
- 各**料型**（material）的成本占比、平均单价、数量如何？当月与上月对比如何？
- **最近 30 天**每日成本趋势、**最近一周**每日成本构成如何？

便于管理层从采购侧控制成本、优化料型结构。

### 2.2 数据来源

- **唯一数据源**：表 **PurchaseWarehouse**（采购入库表）。
- 使用字段包括：入库日期（warehouseDate）、物料类型（material）、含税总价（totalPriceIncludingTax）、含税单价（unitPriceIncludingTax）、净重（netWeight）、入库单号（receiptNo）等。
- **业务类型分类**：按 **receiptNo** 前两位字母划分：
  - **SH** → 基地收货（基地自采）
  - **TH** → 基地买货
  - 其他 → 协同业务

过滤逻辑会排除「红冲」「撤销」等无效状态，只统计有效入库。

### 2.3 分析内容与计算逻辑

| 分析内容 | 说明 | 计算逻辑 |
|----------|------|----------|
| **今日/本周/本月成本** | 汇总卡片显示金额（万元） | 按入库日期落在「今日」「最近 7 天」「本月 1 日～今天」分别汇总 `totalPriceIncludingTax`，单位转为万元。 |
| **当月平均日成本** | 本月总成本 ÷ 本月已过天数 | 本月 1 日至今天的总成本 ÷ 已过天数，用于衡量日均采购支出。 |
| **日成本趋势（最近 30 天）** | 堆叠面积图 | 按日汇总，每日分为基地收货、基地买货、协同业务三类成本（万元），日期范围：从 30 天前到今天。 |
| **本周成本构成** | 柱状图，最近 7 天 | 按自然日（7 天）汇总，每天三类成本（基地收货/基地买货/协同），单位万元。 |
| **当月基地收货废钢类型成本分布** | 饼图 | 仅 receiptNo 以 SH 开头的记录，按 **material** 字段分类汇总：各料型成本（万元）、占比、平均单价（元/吨）、数量（吨）。 |
| **当月基地买货废钢类型成本分布** | 饼图 | 仅 receiptNo 以 TH 开头的记录，同样按 material 分类汇总成本、占比、均价、数量。 |
| **基地收货/买货 料型单价对比（当月 vs 上月）** | 横向柱状图 | 取当月各料型平均单价（元/吨）与上月同料型平均单价对比，用于观察采购单价变化。 |

所有金额均来自数据库已落地的入库数据，**不包含未来日期**；若系统日期为今天，则不会统计「明天」的入库。

### 2.4 小结（成本分析）

- **看的是**：采购入库成本，按业务类型、料型、时间多维度展示。
- **逻辑是**：从 PurchaseWarehouse 按日期、receiptNo、material 汇总与对比，无预估或摊销。
- **用途**：采购与经营层掌握「钱花在哪、花多少、单价趋势」。

## 三、利润分析模块

### 3.1 模块作用

利润分析用于回答：

- 今日/本周/本月**利润**多少？**销售收入**与**成本**各多少？
- **每笔销售**（发货单）的：销售收入、材料成本、加工成本、利润各多少？
- 最近 30 天**日利润趋势**、最近一周**按日的收入/成本/利润分解**如何？
- 各**成品**的当月与上月**原材料使用量、加工成本**对比如何？

为经营决策提供「每单赚多少、利润从哪来」的透明视图。

### 3.2 数据来源

| 数据项 | 来源 | 说明 |
|--------|------|------|
| 销售笔数、发货单号、发货日期、成品名称、仓库、结算量、销售收入 | **DeliverySettlement**（钢厂结算表） | 每笔销售一条，totalSettlementAmount = 销售收入，settlementQuantity = 结算量（吨）。 |
| 每笔的材料成本、材料构成、LIFO 生产记录 | **MaterialCostCache**（材料成本缓存表） | 按 delivery_number 一条一缓存；未命中时由后台尝试实时 LIFO 计算（见下节）。 |
| 加工成本（元/吨） | **ProcessingCostConfig**（加工成本配置表） | 按成品名称（productName）配置 unitProcessingCost；未配置时使用默认 70 元/吨。成品对比图会读取该表；销售明细单笔加工成本以实际代码为准（当前可能使用配置值或默认 70 元/吨）。 |

利润分析页展示的「材料成本(元)」**只来自 MaterialCostCache（或实时 LIFO 结果）**，不直接读生产表；缓存由定时/手动执行 `sp_update_material_cost_cache` 写入。

### 3.3 分析内容与计算逻辑

| 分析内容 | 说明 | 计算逻辑 |
|----------|------|----------|
| **今日/本周/本月利润** | 汇总卡片（万元） | 从销售明细中按发货日期筛选「今日」「本周」「本月」，分别汇总：利润 = 销售收入 − 材料成本 − 加工成本。 |
| **今日成本明细** | 材料成本 + 加工成本（万元） | 今日所有销售的材料成本之和、加工成本之和，与汇总卡片一致。 |
| **日利润趋势（最近 30 天）** | 堆叠面积图 | 按日汇总销售收入、材料成本、加工成本、利润（万元），日期范围：最近 30 天。 |
| **最近一周利润分解** | 柱状图 + 折线 | 按 7 天分别汇总收入、总成本（材料+加工）、利润；可看到每日收入与成本结构。 |
| **销售明细表** | 每笔发货单一行 | 列：发货单号、发货日期、成品名称、仓库、结算量(吨)、销售收入(元)、材料成本(元)、加工成本(元)、利润(元)。单笔利润 = 销售收入 − 材料成本 − 加工成本。 |
| **材料成本明细（悬停/弹层）** | 单笔的材料构成与 LIFO 批次 | 点击或悬停「材料成本(元)」带 ℹ️ 的单元格，展示：该笔 LIFO 使用的生产记录（生产日期、使用数量、单位成本、本批成本）、按材料类型汇总的 quantity/cost（材料构成）。 |
| **成品对比分析（当月 vs 上月）** | 柱状图 | 按成品汇总：当月/上月「每吨成品原材料使用量」、当月/上月「加工成本(元/吨)」，用于对比不同成品耗料与加工成本变化。 |

加工成本计算：**单笔加工成本 = 结算量(吨) × 该成品在 ProcessingCostConfig 中的单位加工成本(元/吨)**；若无配置则用 70 元/吨。

### 3.4 小结（利润分析）

- **看的是**：以销售（发货单）为维度的收入、材料成本、加工成本与利润。
- **逻辑是**：销售收入来自 DeliverySettlement；材料成本来自 MaterialCostCache（由 LIFO 事先算好）；加工成本来自配置 × 结算量；利润 = 收入 − 材料成本 − 加工成本。
- **用途**：经营层与财务看清每单赚多少、成本结构，以及趋势与成品间差异。

## 四、材料成本构成与 LIFO 设计（重点）

利润分析中的「材料成本(元)」是**每笔销售对应的原材料成本**，由**材料成本构成**与 **LIFO（后进先出）** 共同决定。本节说明：材料成本从哪里来、如何构成、LIFO 是什么、为什么采用 LIFO。

### 4.1 材料成本从哪里来

- 页面显示的「材料成本(元)」**只从表 MaterialCostCache 读取**（按发货单号 delivery_number 取一条）。
- MaterialCostCache 中的记录**不是手工录入**，而是由系统按**每笔销售**调用 LIFO 计算后**写入**的。
- 计算与写入由 MySQL 存储过程完成：
  - **sp_update_material_cost_cache(开始日期, 结束日期)**：在 DeliverySettlement 中选出该日期范围内的每笔销售，对每一笔调用 **sp_calculate_lifo_material_cost**，把得到的 material_cost、material_composition、production_records 等写入或更新 MaterialCostCache。
- 因此：**所有展示的材料成本都是「先按 LIFO 算好、再写入缓存」的结果**；没有缓存或缓存未更新，对应发货单的材料成本会为 0 或旧值。

### 4.2 材料成本的「构成」是什么

对**单笔销售**，材料成本有两层含义：

1. **总金额**：该笔销售对应的**材料成本总价（元）**，即 MaterialCostCache.material_cost。
2. **构成明细**：这批成本是由**哪些原材料、各用了多少吨、各占多少金额**组成的，即 MaterialCostCache.material_composition（JSON），形如：
   - `[{ "material": "M2", "quantity": 12.5, "cost": 26250 }, { "material": "M4", "quantity": 8.2, "cost": 16810 }, …]`

利润分析页在「销售明细」表中，对材料成本单元格提供**悬停/点击**，展示的就是上述**材料构成**以及**参与计算的 LIFO 生产记录**（见下），便于核对「这笔单子用了哪几批生产、各批用了哪些料」。

### 4.3 LIFO（后进先出）是什么

- **LIFO** = Last In, First Out，即**后进先出**：假定**最近生产的成品先被销售出去**。
- 在系统中：
  - **输入**：一笔销售——发货单号、成品名称、成品库代码（如 B1、C1）、发货日期、结算量（吨）。
  - **输出**：该笔销售应承担的**材料成本总价**、**材料构成**（各材料类型的 quantity、cost）、以及**参与计算的生产记录列表**（生产日期、使用数量、单位成本、本批成本）。

计算步骤简述：

1. 在 **ProcessingCostInput**（生产加工录入表）中，找出所有满足条件的生产记录：
   - 成品名称、成品库代码与当前销售一致；
   - 生产日期 **≤ 发货日期**；
   - 产量（dailyProcess_qty）> 0。
2. 将这些记录按**生产日期从晚到早**排序（**后生产的排前面**）。
3. 对每一条生产记录，先计算该批的**单位材料成本**：
   - 单位材料成本 = （该批 M1_qty×M1_price + M2_qty×M2_price + … + 各材料列 qty×price 之和）÷ 该批产量（dailyProcess_qty）。
4. 从「待摊销量」= 本笔销售结算量开始，按**排序后的生产记录**依次「消耗」：
   - 本批可用量 = 该条生产记录的产量；
   - 本批使用量 = min(本批可用量, 待摊销量)；
   - 本批材料成本 = 本批使用量 × 该批单位材料成本；
   - 待摊销量 -= 本批使用量；若待摊销量 ≤ 0 则停止。
5. 把所有「本批材料成本」相加，得到该笔销售的**材料成本总价**；同时按材料类型汇总各批的用量与金额，得到 **material_composition**。

因此：**同一笔销售，对应的材料成本完全由「该成品、该库区、生产日期 ≤ 发货日期的生产记录」按 LIFO 顺序摊算得出**，与采购入库的「时间」没有直接关系，只与**生产录入中的用量与单价**有关。

### 4.4 为什么采用 LIFO 设计

1. **符合废钢加工业务习惯**  
   废钢加工通常是：先生产出成品入库存，再按销售订单发货。实际发出去的货，一般会优先发**最近生产的**（库存轮转）。LIFO 假设「后生产的先卖」，与这种**先进库的后出**的物理/管理习惯一致，便于用「最近成本」匹配「当前销售」，利润更贴近当前价格水平。

2. **价格波动大，用最近成本更贴近现时**  
   废钢采购价波动大；若用「先进先出」（FIFO），会把很早以前的生产成本算到当前销售上，利润会偏离当前市场。LIFO 用**最近一批或几批生产**的成本来匹配当前销售，使**材料成本更接近当前采购与生产水平**，报表更反映当下经营结果。

3. **可追溯、可审计**  
   每笔销售的材料成本都对应到**具体生产记录**（生产日期、产量、单位成本），并写入 MaterialCostCache 的 production_records、material_composition。审计或排查时，可以清楚看到「这笔单子用了哪几天的生产、各用了多少吨、各批成本多少」，便于核对与解释。

4. **性能与稳定性**  
   LIFO 计算涉及多表、多行与日期比较，若在每次打开利润分析页时实时算，会慢且易超时。因此采用「**先算后存**」：由定时任务或手动执行 `sp_update_material_cost_cache` 批量算好并写入 MaterialCostCache，前端只读缓存。这样页面响应快，且不会因为某次实时计算异常导致整页失败。

### 4.5 与 LIFO 相关的表与概念（避免混淆）

| 表/概念 | 含义 | 说明 |
|---------|------|------|
| **DeliverySettlement** | 钢厂结算表（销售） | 每笔销售一条：delivery_number、delivery_date、product_type（成品名）、warehouse（成品库代码 A1/B1/C1/D2 等）、settlement_quantity、totalSettlementAmount。 |
| **ProcessingCostInput** | 生产加工录入表 | 每条为「某日某成品某库区的生产」：product_name、product_warehouse（成品库代码）、production_date、dailyProcess_qty（产量），以及 M1_qty/M1_price、M2_qty/M2_price… 等各材料用量与单价。LIFO 用这些列算每批的**单位材料成本**。 |
| **MaterialCostCache** | 材料成本缓存表 | 按 delivery_number 存每笔销售的材料成本、材料构成、参与 LIFO 的生产记录等；由 sp_update_material_cost_cache 写入，利润分析页只读此表。 |
| **成品库代码** | A1、B1、C1、D2 等 | 用于区分同一成品不同库位/产线，对应 ProductStock.warehouse_code、ProcessingCostInput.product_warehouse、DeliverySettlement.warehouse。 |
| **毛料库区** | 如「毛料库八」「毛料库二」 | 在 MaterialStorage 表中为 storage_area，是**毛料**的库区，**不要**与成品库代码 A1/B1 等混用。 |

LIFO 只使用「成品名 + 成品库代码」匹配生产记录；毛料库区用于采购/库存，不参与 LIFO 匹配。

### 4.6 如何更新材料成本缓存（运维要点）

- **不要**对每笔单子单独调用 `sp_calculate_lifo_material_cost`（该过程参数多，用于单笔调试）。
- **应**调用：**sp_update_material_cost_cache(开始日期, 结束日期)**，由该存储过程遍历 DeliverySettlement 并批量写入 MaterialCostCache。
- 示例（在 MySQL 中执行）：
  - 刷新全年：`CALL sp_update_material_cost_cache('2025-01-01', CURDATE());`
  - 只刷新最近 7 天：`CALL sp_update_material_cost_cache(DATE_SUB(CURDATE(), INTERVAL 7 DAY), CURDATE());`
- 平台可配置**每日凌晨定时**执行上述逻辑（如最近 7 天），保证新产生的销售能尽快带上材料成本；历史区间补跑时用上面手动 CALL 即可。

## 五、培训与汇报时可用的「一句话说明」

- **成本分析**：看的是**采购入库花了多少钱**，按业务类型（基地收货/基地买货/协同）、料型、日/周/月汇总与对比，数据全部来自采购入库表。
- **利润分析**：看的是**每笔销售赚多少钱**，收入 − 材料成本 − 加工成本 = 利润；材料成本由**后进先出（LIFO）**按生产记录算好并存入缓存，保证成本可追溯、贴近当前价格、且页面不卡顿。
- **LIFO**：假定「最近生产的先卖」，用最近几批生产的单位材料成本去摊每笔销售量，得到该笔的材料成本与材料构成；这样既符合废钢业务习惯，又使利润更反映当前经营水平，并支持按单、按批追溯。
